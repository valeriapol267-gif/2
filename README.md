# depviz

Инструмент визуализации графа зависимостей Maven-пакетов (Java).
Практическая работа №2 по дисциплине «Конфигурационное управление»,
вариант 22.

## 1. Общее описание

`depviz` - консольное приложение на Python (стандартная библиотека, без
сторонних зависимостей). Менеджеры пакетов и готовые библиотеки для
получения зависимостей не используются.

Что умеет приложение:

1. Принимает параметры из командной строки и проверяет их (этап 1).
2. Скачивает `pom.xml` из Maven-репозитория и находит прямые зависимости
   (этап 2).
3. Строит граф транзитивных зависимостей обходом в глубину без рекурсии с
   ограничением глубины и обработкой циклов; поддерживает тестовый
   репозиторий из файла (этап 3).
4. Показывает обратные зависимости - пакеты, которые зависят от данного
   (этап 4).

Визуализация PlantUML/PNG (этап 5) пока не реализована; опция `--output`
проверяется, но пока не используется.

### Сбор данных (этап 2)

Модуль `depviz/maven.py` скачивает `pom.xml` нужной версии по стандартной
раскладке Maven
(`<repo>/<groupId с / вместо .>/<artifactId>/<version>/<artifactId>-<version>.pom`),
разбирает его через `xml.etree` и вычисляет прямые зависимости: учитывается
наследование от parent-pom (до 10 уровней), подстановка свойств `${...}` и
`dependencyManagement`. Не разворачиваются профили, BOM-импорты
(`scope=import`), исключения (`exclusions`) и диапазоны версий.

### Построение графа (этап 3)

- **DFS без рекурсии** (`depviz/graph.py`): обход выполняется циклом с
  явным стеком, поэтому длинные цепочки зависимостей не вызывают
  `RecursionError`.
- **Максимальная глубина** `--max-depth`: корень имеет глубину 0, зависимости
  корня - 1. При глубине 1 выводятся только прямые зависимости. Пакеты на
  предельной глубине не раскрываются и помечаются «не раскрыт». Если такой
  пакет позже встретится ближе к корню, он будет раскрыт (пример -
  `examples/depth.txt`).
- **Циклы**: пакеты текущего пути хранятся в множестве; при ребре в пакет
  из пути цикл запоминается (один раз, в нормализованном виде) и обход не
  идёт дальше. Самозависимость `G -> G` тоже считается циклом.
- **Общие зависимости** (ромб) попадают в граф один раз.
- **Maven**: узел графа - `groupId:artifactId:version`. У корня учитываются
  все зависимости, у остальных пакетов только транзитивные (без scope
  `test`/`provided`/`system` и без `optional`), как в Maven. Медиация версий
  не выполняется: разные версии одной библиотеки - разные узлы. Если pom
  транзитивной зависимости получить нельзя (нет файла, диапазон версий,
  неразрешённое свойство), узел помечается «данные недоступны», в stderr
  выводится предупреждение, а обход продолжается. Для корня это ошибка.
- **Тестовый режим** (`--test-mode`): вместо URL в `--repo` указывается
  файл, описывающий граф; пакеты называются большими латинскими буквами.

### Формат файла тестового репозитория

Одна строка на пакет:

```
# комментарий
A: B C
B: D, E
C:
D
```

- `A: B C` - пакет A зависит от B и C (разделители - пробелы и запятые);
- `A:` или `A` - у пакета нет зависимостей;
- пустые строки и строки с `#` в начале игнорируются;
- пакет, упомянутый только как зависимость, считается пакетом без
  зависимостей;
- повторное описание пакета, строчные буквы и другие символы - ошибка с
  номером строки.

### Обратные зависимости (этап 4)

Опция `--reverse` (только вместе с `--test-mode`) выводит пакеты, которые
зависят от заданного, в том числе косвенно. Используется тот же обход
`build_graph`: файл тестового репозитория разворачивается в «репозиторий
обратных зависимостей» (`GraphFileRepository.reversed_repository`), и по
нему строится граф от исследуемого пакета. Глубина и циклы обрабатываются
так же, как для прямых зависимостей. В строке `X <- A, B` пакеты A и B
зависят от X.

У реальных Maven-репозиториев нет индекса обратных зависимостей (по URL
можно получить pom конкретного пакета, но не список пакетов, которые на
него ссылаются), поэтому вне тестового режима `--reverse` - ошибка
параметров.

## 2. Описание настроек

Все параметры задаются опциями командной строки.

- `--package` - имя анализируемого пакета `groupId:artifactId`.
  В тестовом режиме - имя из больших латинских букв (`A`, `B`, ...).
  Обязательный параметр.
- `--repo` - URL Maven-репозитория или путь к файлу тестового репозитория.
  По умолчанию `https://repo1.maven.org/maven2`.
- `--test-mode` - режим тестового репозитория: `--repo` задаёт путь к
  файлу. По умолчанию выключен.
- `--version` - версия пакета. Обязательна вне тестового режима, в тестовом
  режиме игнорируется.
- `--output` - имя файла с изображением графа (расширение `.png`).
  По умолчанию `graph.png`. Пока не используется.
- `--max-depth` - максимальная глубина анализа, целое от 1 до 100.
  По умолчанию `3`.
- `--reverse` - показать обратные зависимости (только с `--test-mode`).

Проверки параметров:

- `--package`: вне тестового режима - строго `groupId:artifactId`
  (латиница, цифры, `_`, `.`, `-`); в тестовом режиме - только `A-Z`.
- `--repo`: URL со схемой `http`/`https` и хостом; в тестовом режиме -
  существующий читаемый файл (параметр обязателен).
- `--version`: непустая строка из букв, цифр и `_ . + -`, начинается с
  буквы или цифры.
- `--output`: расширение `.png`, без недопустимых символов, каталог должен
  существовать, имя не может быть каталогом.
- `--max-depth`: целое число в диапазоне 1-100.
- `--reverse`: допустим только вместе с `--test-mode`.

Коды завершения: `0` - успех, `1` - ошибка получения данных (пакет или
версия не найдены, сеть недоступна, некорректный `pom.xml` или файл
тестового репозитория), `2` - ошибка параметров. Сообщения об ошибках
выводятся в stderr.

## 3. Запуск и тесты

Требуется Python 3.9+. Приложение запускается как модуль `depviz`; каталог
`src` должен быть в `PYTHONPATH`.

Windows (PowerShell), из корня проекта:

```
$env:PYTHONPATH = "src"
py -m depviz --package org.apache.httpcomponents:httpclient --version 4.5.14
```

Linux/macOS:

```
PYTHONPATH=src python3 -m depviz --package org.apache.httpcomponents:httpclient --version 4.5.14
```

Те же запуски через скрипты (они сами задают `PYTHONPATH`):

```
.\run.bat --package org.apache.httpcomponents:httpclient --version 4.5.14
sh run.sh --package org.apache.httpcomponents:httpclient --version 4.5.14
```

Первая команда - для PowerShell, вторая - для Linux/macOS.

Тесты (стандартный `unittest`, `PYTHONPATH` не нужен):

```
py -m unittest discover -s tests -t . -v
python3 -m unittest discover -s tests -t . -v
```

Первая команда - для Windows, вторая - для Linux/macOS.

В PyCharm каталог `src` нужно пометить как Sources Root.

## 4. Примеры (тестовый репозиторий, каталог `examples/`)

В примерах первая строка блока - команда (для Windows вместо `python`
используйте `py`, предварительно выполнив `$env:PYTHONPATH = "src"`),
остальные строки - вывод.

Ромб - общая зависимость D в графе один раз:

```
python -m depviz --test-mode --package A --repo examples/diamond.txt
Граф зависимостей A (макс. глубина 3):
  A -> B, C
  B -> D
  D -> (нет зависимостей)
  C -> D
Узлов: 4, рёбер: 4
Циклических зависимостей нет.
```

Цикл:

```
python -m depviz --test-mode --package A --repo examples/cycle.txt
Граф зависимостей A (макс. глубина 3):
  A -> B
  B -> C
  C -> A
Узлов: 3, рёбер: 3
Циклические зависимости (1):
  A -> B -> C -> A
```

Несколько циклов, самопетля и пакет X, не описанный в файле
(`--max-depth 5`):

```
python -m depviz --test-mode --package A --repo examples/complex.txt --max-depth 5
Граф зависимостей A (макс. глубина 5):
  A -> B, C
  B -> D, E
  D -> A
  E -> F, G
  F -> H, X
  H -> (нет зависимостей)
  X -> (нет зависимостей)
  G -> G
  C -> F
Узлов: 9, рёбер: 11
Циклические зависимости (2):
  A -> B -> D -> A
  G -> G
```

Ограничение глубины (глубина 1 - только прямые зависимости):

```
python -m depviz --test-mode --package A --repo examples/complex.txt --max-depth 1
Граф зависимостей A (макс. глубина 1):
  A -> B, C
  B -> (не раскрыт: достигнута максимальная глубина)
  C -> (не раскрыт: достигнута максимальная глубина)
Узлов: 3, рёбер: 2
Циклических зависимостей нет.
```

Повторное раскрытие пакета, впервые найденного на предельной глубине
(D сначала достигнут через A -> B -> C -> D, потом напрямую из A):

```
python -m depviz --test-mode --package A --repo examples/depth.txt
Граф зависимостей A (макс. глубина 3):
  A -> B, D
  B -> C
  C -> D
  D -> E
  E -> (нет зависимостей)
Узлов: 5, рёбер: 5
Циклических зависимостей нет.
```

Ошибки тестового режима:

```
python -m depviz --test-mode --package Z --repo examples/complex.txt
Ошибка: пакет Z не описан в тестовом репозитории.

python -m depviz --test-mode --package A --repo bad.txt
Ошибка: строка 2: ожидается формат 'A: B C', получено 'bad line'.
```

### Обратные зависимости

Кто зависит от D (прямо и косвенно):

```
python -m depviz --test-mode --reverse --package D --repo examples/diamond.txt
Обратные зависимости D (макс. глубина 3):
  D <- B, C
  B <- A
  A <- (нет зависимых пакетов)
  C <- A
Узлов: 4, рёбер: 4
Циклических зависимостей нет.
```

Обратные зависимости с циклом (A используется пакетом D, D - пакетом B,
B - пакетом A):

```
python -m depviz --test-mode --reverse --package A --repo examples/complex.txt --max-depth 5
Обратные зависимости A (макс. глубина 5):
  A <- D
  D <- B
  B <- A
Узлов: 3, рёбер: 3
Циклические зависимости (1):
  A <- D <- B <- A
```

Пакет, на который ссылаются несколько ветвей:

```
python -m depviz --test-mode --reverse --package F --repo examples/complex.txt --max-depth 5
Обратные зависимости F (макс. глубина 5):
  F <- C, E
  C <- A
  A <- D
  D <- B
  B <- A
  E <- B
Узлов: 6, рёбер: 7
Циклические зависимости (1):
  A <- D <- B <- A
```

Ограничение глубины и ошибка вне тестового режима:

```
python -m depviz --test-mode --reverse --package X --repo examples/complex.txt --max-depth 2
Обратные зависимости X (макс. глубина 2):
  X <- F
  F <- C, E
  C <- (не раскрыт: достигнута максимальная глубина)
  E <- (не раскрыт: достигнута максимальная глубина)
Узлов: 4, рёбер: 3
Циклических зависимостей нет.

python -m depviz --reverse --package a:b --version 1
Ошибка параметров: режим --reverse поддерживается только вместе с --test-mode: у Maven-репозитория нет индекса
обратных зависимостей.
```
